# 原始数据质量审计

## 一、审计范围

本次审计对象为UCI Online Retail原始交易数据。

本阶段只执行读取、统计和异常识别，没有删除、填补、转换或覆盖任何原始数据。

## 二、数据基本情况

- 数据行数：541,909
- 字段数量：8
- 不同订单编号数：25,900
- 不同商品编号数：4,070
- 不同客户数：4,372
- 不同国家或地区数：38
- 最早交易时间：2010-12-01 08:26:00
- 最晚交易时间：2011-12-09 12:50:00

## 三、缺失值

| 字段 | 缺失数量 | 缺失比例 |
|---|---:|---:|
| CustomerID | 135,080 | 24.93% |
| Description | 1,454 | 0.27% |
| 其他字段 | 0 | 0.00% |

所有缺少Description的记录也同时缺少CustomerID。

客户编号缺失的记录不能直接用于客户级分析和RFM分层，但是否保留用于整体经营分析，需要在清洗阶段结合业务目标决定。

## 四、重复数据

共发现5,268个完全重复行。

本阶段没有删除重复记录。后续需要评估这些记录是重复导入，还是缺少明细行编号导致的真实重复商品记录，并比较删除前后对指标的影响。

## 五、数量检查

- 数量小于0：10,624行
- 数量等于0：0行
- 数量大于0：531,285行
- 最小数量：-80,995
- 最大数量：80,995

负数量可能包含取消订单、退货、库存调整或其他非正常交易，需要结合订单编号和商品描述分类处理。

## 六、单价检查

- 单价小于0：2行
- 单价等于0：2,515行
- 单价大于0：539,392行
- 最小单价：-11,062.06
- 最大单价：38,970.00

零价格和负价格记录不能直接作为正常商品销售，需要在清洗阶段检查其商品编码和描述。

## 七、取消订单检查

- 订单编号以C开头：9,288行
- C开头且数量为负：9,288行
- C开头但数量非负：0行
- 数量为负但订单编号不以C开头：1,336行

所有C开头记录都具有负数量，但不是所有负数量记录都以C开头。因此后续不能只依赖数量正负判断订单状态。

## 八、字段类型问题

完整数据中的CustomerID被pandas读取为浮点数。客户编号是标识符，不具有数学含义。

该现象可能与CustomerID存在缺失值有关。清洗阶段应在保留缺失状态的前提下，将有效客户编号转换为字符串。

InvoiceNo和StockCode同样属于标识符，应按照文本或分类变量处理。

## 九、时间范围限制

2011年12月的数据只覆盖到12月9日，不是完整月份。

后续分析月度销售趋势时，不能直接将2011年12月与其他完整月份比较，必须明确标注或排除不完整月份。

## 十、主要数据质量问题

1. CustomerID缺失比例较高。
2. Description存在少量缺失。
3. 存在完全重复记录。
4. 存在取消订单和负数量记录。
5. 存在非C开头的负数量记录。
6. 存在零价格和负价格记录。
7. 数量和单价存在极端值。
8. StockCode中可能包含非普通商品编码。
9. CustomerID的数据类型不适合作为客户标识。
10. 数据最后一个月份不完整。

## 十一、下一阶段需要制定的规则

下一阶段需要分别决定：

1. 完全重复行如何处理。
2. 缺失CustomerID的记录在哪些分析中保留。
3. 缺失Description的记录如何处理。
4. 取消订单如何标记。
5. 非C开头负数量记录如何分类。
6. 零价格和负价格记录如何处理。
7. 特殊商品编码如何分类。
8. 极端值是否属于真实批发交易。
9. 客户编号如何转换为字符串。
10. 如何验证清洗前后的数据变化。
