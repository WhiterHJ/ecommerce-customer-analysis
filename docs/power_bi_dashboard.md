# Power BI 可视化仪表盘

## 仪表盘目标

本仪表盘使用清洗后的电商交易明细和RFM客户分层结果，从经营表现、市场与商品、客户价值三个角度展示分析结果。

仪表盘包含三个交互式页面：

1. 经营总览
2. 市场与商品
3. 客户分层

[下载Power BI源文件](../powerbi/ecommerce_customer_analysis.pbix)

[查看DAX定义](../powerbi/measures.dax)

## 数据来源

仪表盘使用以下两个数据表：

| 数据表 | 粒度 | 用途 |
|---|---|---|
| `transactions` | 每行一条清洗后的交易明细 | 计算销售额、订单量、取消金额、市场和商品指标 |
| `customer_rfm` | 每行一名可识别客户 | 计算RFM指标和客户分层结果 |

完整交易数据包含536,641行。RFM客户表包含4,338名具有客户编号且发生正常销售的客户。

原始数据来自UCI Machine Learning Repository的[Online Retail数据集](https://archive.ics.uci.edu/dataset/352/online+retail)。

## 数据模型

仪表盘使用一个交易事实表和两个维度表：

```text
customer_rfm[CustomerID]  1 ─── *  transactions[CustomerID]

DateTable[Date]           1 ─── *  transactions[InvoiceDateOnly]
```

两条关系均为活动的单向一对多关系。

- `transactions`保存交易明细。
- `customer_rfm`保存客户级RFM结果。
- `DateTable`用于按日期和月份筛选交易。
- `InvoiceDateOnly`从交易时间中提取纯日期，用于连接日期表。

## 核心指标

| 指标 | 结果 | 计算口径 |
|---|---:|---|
| 正常销售额 | £10,642,110.80 | 正常销售记录的行金额合计 |
| 正常销售订单数 | 19,960 | 正常销售订单编号去重计数 |
| 可识别客户数 | 4,338 | 具有客户编号的正常销售客户去重计数 |
| 平均订单金额 | £533.17 | 正常销售额除以正常销售订单数 |
| 取消金额 | £893,979.73 | 取消交易行金额绝对值合计 |
| 取消金额占比 | 8.40% | 取消金额除以正常销售额 |
| 复购客户率 | 65.58% | 购买至少两次的客户占可识别客户的比例 |
| Champions客户数 | 911 | 被划分为Champions的客户数量 |
| Champions销售额占比 | 63.87% | Champions销售额占可识别客户销售额的比例 |
| At Risk客户数 | 534 | 被划分为At Risk的客户数量 |

Power BI结果已经与SQL和Python分析结果进行核对，核心指标全部一致。

## 交互设计

- 国家筛选器用于查看特定市场的经营表现。
- 月份筛选器用于查看特定月份指标。
- RFM筛选器用于查看不同客户群体。
- 图表、卡片和明细表会根据当前筛选条件动态更新。

## 数据限制

- 数据时间范围为2010年12月至2011年12月，不能代表当前电商市场。
- 2011年12月只有9天数据，不能与完整月份直接比较。
- 约四分之一的原始交易记录缺少客户编号，因此客户和RFM分析只覆盖可识别客户。
- 商品`23843`存在单笔超大数量订单，对销量排名影响明显。
- PBIX采用导入模式。打开文件可以查看已有结果，但刷新数据时需要重新生成本地CSV文件。
- 仪表盘用于展示历史经营分析方法，不直接构成现实经营决策建议。
