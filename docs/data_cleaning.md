# 数据清洗规则与结果

## 一、清洗目标
对原始交易数据进行去重、字段标准化和业务分类，在不虚构缺失信息的前提下，生成可分析、可追溯的数据集。

## 二、清洗原则
1. 原始Excel只读取，不覆盖。
2. 不虚构缺失的客户编号和商品描述。
3. 取消、调整和特殊交易分类保留，不直接删除。
4. 每项清洗规则均保留代码和文字记录。
5. 完整清洗数据仅保存在本地，GitHub提供1,000行固定随机样本。


## 三、重复记录处理
保留第一次出现的记录，删除后续完全重复记录

## 四、缺失值处理
CustomerID 缺失	不删除；增加 HasCustomerID 标记，客户分析时再排除
Description 缺失	保留缺失状态，不虚构商品名称

## 五、交易类型分类
C 开头订单	标记为 Cancellation
非 C 开头但数量为负	标记为 StockAdjustment
正数量、零价格	标记为 ZeroPrice
负价格	标记为 PriceAdjustment
正数量、正价格、非 C 订单	标记为 Sale

## 六、特殊商品编码处理
特殊 StockCode	分类标记，不直接删除
极端数量和价格	暂时保留，不进行截断或替换

## 七、字段格式转换
CustomerID	转换为字符串，去掉 .0
InvoiceNo、StockCode	转换为字符串、去除首尾空格、统一为大写


## 八、清洗结果
原始数据541,909行。
删除完全重复记录5,268行。
清洗后保留536,641行。
缺失CustomerID没有删除，仅在客户分析中排除。
取消、库存调整、价格调整和零价格记录被分类保留。
特殊StockCode被标记为不同ItemType。
极端值暂时保留。

GitHub只提供固定随机种子的1,000行样本。
删除重复行属于分析假设，因为原始数据没有明细行唯一编号。
## 九、输出文件
transactions_clean.csv：536,641行，仅保存在本地。
transactions_clean_sample.csv：固定随机抽取1,000行，上传GitHub。

## 十、已知限制
1. 2011年12月数据只到9日，不是完整的一个月，之后月度分析时需要说明。
2. UCI元数据将该数据集标记为无缺失值，但实际文件存在CustomerID和Description缺失，本项目以实际审计结果为准。
3. CustomerID缺失记录不能用于客户级分析，后续RFM结果仅代表具有客户编号的销售记录。
4. 原始数据没有明细行唯一编号，将完全相同记录视为重复记录属于本项目的分析假设。
